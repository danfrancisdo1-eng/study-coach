## 2026-10-11 — D-052: Sets of six or more are written in two parts; the first three questions come back with the reply
- Dan (at the Mac, 2026-10-11): "Let's move to an in-chat preview for the questions. One question at a time." Before that can feel live, the wait had to go: one chat request ran the coach's reply, the whole set and the answer-key check in a row, and the phone showed "Coach is working… up to a minute" until all three were done. Built, server side (first of the two commits for D-051): a chat-first set of six or more questions is written in two parts. The first three are written and checked before the reply goes out, so the phone has the reply and the first card in about ten seconds; the rest is written and checked after the reply, in the background, and appended to the stored session. The set carries `writing: { startedAt }` meanwhile; the public session and the chat's `activeQuiz` now report `status: writing | ready`, and `total` is the size the set will have while it is writing. Answers on the first part are taken while the rest is written (the background save retries on a version race with them); grading answers 409 "still writing" until the rest is in. A failed second part leaves the set as its first part, the missing questions counted as invalid; a writer that died (no save for three minutes) is treated the same, so a set is never stuck. Sets under six are written in one go as before. "Missed topics" sets still carry one or two earlier correct questions; they go in with the second part. No prompt text changed (the writer is simply asked for 3, then for the rest with the first part's prompts listed as taken), so no prompt version bump and no eval run.
- Phone (same commit): the set sheet polls the session every 1.5 s while the status is writing, counts "Question 2 of 10" against the whole set, and shows "Writing question 4…" instead of Grade when the first part is answered before the rest lands. The chat's busy line reads "Coach is writing the first questions…".
- Not built here: the live card in the chat itself (next commit), and true token streaming (the Anthropic client in `ai/anthropic.ts` is non-streaming and the structured JSON output would need an incremental parser; two parts give the student the first card in seconds without either).
- Verified here: typecheck (all packages); 109/109 tests, including a new end-to-end test for the two-part flow (answer during writing, 409 on grade, second writer told the first part's prompts, failed second part) and 3 unit tests for the status rule; iOS bundle export.
